# インターフェースの終わりはスローガンではない：Telepathy はいかにして協働を対話から意味直結へと進化させるのか

ここ二年、人々は「自然言語」を高々と持ち上げてきた。  
まるで AI と会話できるようになっただけで、人類は新たな時代に突入したかのように。

対話インターフェースが大きな進歩であることは、私も認める。  
だが、本気で AI を社会の一員にしたいと考えるなら、すぐに一枚の壁にぶつかるはずだ。  
**対話は協働の言語ではない。**

人と人が協働できるのは、おしゃべりが上手いからではなく、同じ意味の協定を共有しているからだ。  
契約、伝票、証憑、フロー、役割、責任、申し立て……これらはどれも「会話で片付くもの」ではない。  
会話でそれらを描写することはできても、会話でそれらを置き換えることはできない。

iFay と coFay が協働を始め、Fay 同士が公共サービスを引き受け始め、AI が人に代わって「対外的に手を出す」ようになったとき——  
会話は最も高くつくボトルネックになる。遅く、曖昧で、誤解されやすく、監査も振り返りも難しい。

これこそが、Telepathy Protocol が解こうとしている問題だ。

## 1. 「UI を捨てる」のはカッコつけのためではなく、情報損失を避けるため

UI の本質は翻訳層だ。意図をインターフェースに翻訳し、インターフェースを操作に翻訳し、操作をシステム呼び出しに翻訳する。  
人間が操作する時代には、視覚的可読性が必要だったからこそ、この翻訳層は理にかなっていた。

ところが Fay が協働に参加するようになると、UI はきわめて見えにくい形で情報損失を生み出す。

- 人間に読める表現は、多くの場合、機械にとって最も精確な表現ではない。  
- 機械が精確に実行できる構造は、UI によって一文の自然言語に均されてしまう。  
- 最終的に手にするのは協働ではなく、「口約束」にすぎない。

協働が責任を伴う段階に入れば、口約束では足りない。  
必要なのは、監査可能な意味構造だ。

だから Telepathy は「UI を捨てる」のではなく、「UI という翻訳層を捨てる」のだ。  
Fay と Fay の間で、テキストではなく、意味と意図を直接受け渡せるようにすることを目指している。

## 2. 対話の弱点：責任が意味のなかで蒸発してしまう

今日の AI に対する最大の誤解の一つは、「会話能力」を「責任能力」と取り違えていることだ。  
人間っぽく会話できるからといって、それが社会的責任を担えることを意味するわけではない。

coFay が公共的な役割として意思決定を行うとき、社会が求めるのはこういうことだ。

- どのルールにもとづいたのか？  
- どのデータを呼び出したのか？  
- どの動作をトリガーしたのか？  
- どこまでの権限の中での行為だったのか？  
- 誤りが起きた後、どう申し立て、どう振り返り、どう責任を追及するのか？

これらすべてがチャットログの中に埋もれているなら、責任は意味のなかで蒸発してしまう。  
チャットログはいつでも解釈し直せ、語り直せ、切り貼りできる。制度的な確定性を持っていない。

私は、未来の公共サービスが「あなたと AI が口論する場」になることを望まない。  
そうではなく、「検証可能な意思決定の構造を一通り受け取れる場」であってほしいと思っている。

## 3. Telepathy の方向性：token（ベクトル符号化）でテキストに代わり、構造化された意味を運ぶ

Telepathy の核心的なやり方はこうだ。  
取り決められた token（ベクトル符号化）に意味を担わせ、構造化されたテキストにそれを担わせない。

抽象的に聞こえるかもしれないが、二つの時代の違いになぞらえて考えてみるとよい。

- かつて：人が人に手紙（自然言語）を書くことでも協働はできたが、効率は極端に低く、振り返りも難しかった。  
- いま：我々はプロトコルスタック（HTTP/TLS/OAuth）で協働しており、意味はプロトコル化され、責任の境界はかっちりと打ち込まれている。

Telepathy は、Fay の世界における「プロトコルスタック」になろうとしている。  
iFay と coFay が互いに UI を見せる必要も、意味を一文に押しつぶす必要もなくなる。  
両者は構造化された意味を直接やり取りすることができ、それによって協働の効率も正しさも一段引き上げられる。

## 4. 「協働効率」は表層にすぎず、本当の核心は「ガバナンス可能性」

私は Telepathy を「より速い」とだけ語りたくはない。  
ガバナンスできない、より速いシステムは、より危険なだけだ。

Telepathy の真の価値は、ガバナンスを可能にする点にある。

- 意味がプロトコル化されれば、ある token 列が何を意味するのかを監査できるようになる。  
- アクセス制御ができるようになる。どの token がどの権限の下でなら現れてよいのか。  
- 振り返りができるようになる。協働の連なりにおける「意味の交換」一回ごとがトレースできる。  
- 申し立てができるようになる。争点はもはや「あなたの理解違いだ」ではなく、「プロトコル構造はルールに沿っていたか」になる。

これこそ、私がずっと強調してきた方向性だ。AI を野放しにしてはならず、人の監護のもとで動かなければならない。  
監護とは単なるブレーキではなく、説明可能性、申し立て可能性、責任追及可能性までを含む。

## 5. Telepathy と iFay / coFay：公共的役割を本当に使えるものにする

未来の病院のシーンを想像してみてほしい。

あなたの iFay が、症状、既往歴、リスク選好、プライバシー境界を、Telepathy の意味として直接、病院の coFay に送る。  
病院の coFay は、あなたに同じ説明を十回繰り返させる必要もなく、UI フォームで情報を取りこぼすこともない。  
その coFay が示すトリアージと提案は、「対話風の返信」ではなく、監査可能な意思決定構造として届く——根拠、ルール、動作、申し立て窓口まで含めて。

このときはじめて、公共サービスが本当に AI に引き受けられる可能性が出てくる。  
依拠するのはもはや「会話が人間っぽいかどうか」ではなく、「制度が制度らしくあるかどうか」だからだ。

## 6. 結び：インターフェースの終わりとは、人をシステムから蹴り出すことではなく、翻訳層を蹴り出すこと

私が「インターフェースの終わり」と言うとき、それは人類にインターフェースが要らないという意味ではない。  
人は常に、読めて、コントロール可能な表示の仕方を必要としている。  
システムから蹴り出されるのは、意味を絶えず損ない、責任を絶えず蒸発させてしまう、あの UI という翻訳層のほうだ。

Telepathy が意味するのは、こういうことだ。  
協働を、対話から意味直結へと進化させること。  
Fay 同士を、プロトコルスタックのように協働させること。  
公共サービスや社会的役割を、本当の意味でガバナンス可能にすること。

AI が社会の一員になるなら、この一歩はいずれ踏み出されることになる。
